# Ticket Breakdown — Phase 7: Agent Layer (LangGraph Ops Copilot)

## Epic Summary
Implement the LangGraph Ops Copilot agent layer for the Logistics Demand & ETA Forecasting Platform. The agent serves as the pipeline's conversational observability and operational differentiator, transforming static forecasts and dashboards into an explainable interface that queries live system state directly. The agent incorporates four purpose-built read-only tools (`get_features`, `query_recent_predictions`, `query_pipeline_status`, `search_logs_and_model_cards`), utilizes a scoped FAISS CPU vector index over platform documentation and model metadata, implements a dual-LLM provider strategy (Groq primary, Gemini fallback, and a deterministic offline mock provider), enforces strict prompt-injection guardrails where tool allowlisting is the definitive security boundary, and exposes conversational capabilities via FastAPI `/agent/chat` and an interactive Streamlit UI copilot interface.

---

## Architectural Decisions & Constraints

1. **ADR-023: LangGraph Ops Copilot Framework & Tool Execution Architecture**:
   - **Decision:** Build the agent using LangGraph `StateGraph` with an explicit tool allowlist and typed state (`AgentState`), rather than an unconstrained single-agent ReAct loop.
   - **Rationale:** Tool calls query live infrastructure (PostgreSQL, Feast Redis, FAISS). LangGraph guarantees predictable, debuggable execution order, bounded recursion limits, and deterministic state tracking.
   - **Security Boundary:** The definitive security boundary against prompt injection and unauthorized actions is strict **read-only tool allowlisting** (ground rules #3 & #4, Security.md §4). Keyword filtering or prompt steering is strictly an advisory defense-in-depth layer; the structural security guarantee is that the agent cannot execute commands, write data, or invoke unallowlisted tools.

2. **ADR-024: Dual-Provider LLM Fallback & Hermetic Mock Engine**:
   - **Decision:** Groq as primary LLM (`llama-3.3-70b-versatile` / `llama-3.1-8b-instant`), Google Gemini as fallback (`gemini-2.0-flash` / `gemini-1.5-flash`), and an explicit deterministic mock provider when API keys are absent.
   - **Rationale:** Groq provides ultra-fast inference (<1s); Gemini provides high-availability redundancy. The mock engine ensures 100% test reliability and hermetic CI execution without external network or API secret dependencies.
   - **Explicit Labeling:** All responses generated by the mock provider must be explicitly tagged with `provider: "mock"` in metadata and labeled with `[MOCK / OFFLINE MODE]` in response headers so users and automated tests never mistake mock output for live LLM inference.

3. **ADR-025: FAISS CPU Vector Index & Artifact Scoping**:
   - **Decision:** Use a self-contained, CPU-backed FAISS vector store indexing strictly repository artifacts (`docs/*.md`, MLflow model cards/registry metadata, and recent pipeline run summaries) with lightweight ONNX embeddings (`fastembed` / `all-MiniLM-L6-v2`) and local vector fallback.
   - **Rationale:** Minimal memory footprint on the Oracle Always Free VM, zero external vector database dependencies, and tight scoping to platform design documents.

4. **Prediction Persistence Requirement**:
   - All live predictions served by FastAPI `/predict/demand` and `/predict/eta` must be logged to `warehouse.predictions` (Ground Rule #3) so the agent's `query_recent_predictions` tool has genuine live prediction history to inspect.

## Tickets

### M7-1: Core Agent Tools & Serving Prediction Logging Integration
- **Scope / Acceptance Criteria:**
  - **Prediction Logging in Serving:**
    - Update `src/serving/app.py` to record predictions to PostgreSQL `warehouse.predictions` (using FastAPI `BackgroundTasks` to preserve sub-5ms cached latency and sub-20ms uncached latency).
    - Stores `prediction_id` (UUID), `entity_type` ('zone' or 'corridor'), `entity_id`, `model_version`, `predicted_value`, and `predicted_at` (UTC timestamp).
  - **Core Agent Tools in `src/agents/tools.py`:**
    - Tool 1 (`get_features`): Queries Feast Redis online store for feature vectors (`zone_demand_features` or `corridor_duration_features`) using `get_online_client()`. Returns structured dict with `features`, `cache_hit`, and `retrieved_at`. Validates entity IDs (zone $\in [1, 263]$, corridor in `orig_dest` format). Handles degraded/cold cache with imputed defaults and warnings.
    - Tool 2 (`query_recent_predictions`): Queries `warehouse.predictions` for recent inference outputs within a given lookback window (default 24 hours). Returns list of predictions with timestamps, values, and model versions.
    - Tool 3 (`query_pipeline_status`): Queries `warehouse.pipeline_runs` for latest batch/streaming/retraining runs, durations, records processed, and failure messages. Computes overall status (`healthy`, `degraded`, `empty`).
    - Tool 4 (`search_logs_and_model_cards`): Interfaces with the FAISS RAG index (or stub/retriever) to return relevant document chunks with title, source, and relevance score.
  - All tools are strictly read-only, type-annotated with Pydantic/typing, and handle missing entities or database connection errors gracefully without crashing.
  - Comprehensive unit and integration tests in `tests/test_agent_tools.py` verifying tool outputs against mock and live PostgreSQL/Redis schemas.
- **Per-Ticket Context:** `src/serving/app.py`, `src/common/models.py`, `src/features/client.py`, `docs/Agents.md`.
- **Files Touched:** `src/serving/app.py`, `src/agents/tools.py`, `src/agents/__init__.py`, `tests/test_agent_tools.py`.
- **Estimated Size:** ~350 lines.
- **Depends On:** Phase 5 serving stack, Phase 6 retraining flow.

### M7-2: FAISS RAG Indexer & Knowledge Retrieval Engine (ADR-025)
- **Scope / Acceptance Criteria:**
  - Implement document chunker and metadata extractor in `src/agents/rag/indexer.py`:
    - Ingests and chunks `docs/*.md` (Architecture, Decisions, Database, Security, Roadmap, Environment-Setup, etc.).
    - Extracts registered model metadata from MLflow tracking/registry.
    - Summarizes recent pipeline execution logs from `warehouse.pipeline_runs`.
  - Implement vector store builder in `src/agents/rag/store.py`:
    - Builds CPU-backed FAISS index with `fastembed` (quantized `BAAI/bge-small-en-v1.5` or `all-MiniLM-L6-v2`) and local deterministic token vectorizer fallback.
    - Persists serialized FAISS index and chunk metadata to `artifacts/rag_index/`.
  - Implement retriever in `src/agents/rag/retriever.py`:
    - Semantic search with similarity threshold and top-$k$ ranking.
    - Formats retrieved chunks with document title, section heading, file path, and relevance score.
  - CLI script `scripts/build_rag_index.py` for manual or scheduled re-indexing.
  - Unit and contract tests in `tests/test_rag_indexer.py`.
- **Per-Ticket Context:** `docs/*.md`, `src/agents/tools.py`, `docs/Decisions.md` (ADR-025).
- **Files Touched:** `src/agents/rag/indexer.py`, `src/agents/rag/store.py`, `src/agents/rag/retriever.py`, `scripts/build_rag_index.py`, `tests/test_rag_indexer.py`.
- **Estimated Size:** ~400 lines.
- **Depends On:** M7-1.

### M7-3: LangGraph Ops Copilot, Fallback Router & Guardrails (ADR-023, ADR-024)
- **Scope / Acceptance Criteria:**
  - Define agent state schema in `src/agents/state.py` (`messages`, `tools_used`, `sources`, `provider`, `latency_ms`, `status`).
  - Implement LangGraph workflow in `src/agents/graph.py`:
    - Primary LLM: Groq (`llama-3.3-70b-versatile` / `llama-3.1-8b-instant`).
    - Fallback LLM: Google Gemini (`gemini-2.0-flash` / `gemini-1.5-flash`).
    - Offline Mock Engine: Deterministic rule-based tool-dispatch and synthesis for testing and CI without API keys.
    - Explicitly labels mock responses (`provider: "mock"`, `[MOCK / OFFLINE MODE]` header).
    - Tool execution node enforcing the 4-tool allowlist.
    - Response synthesis node formatting natural-language answers and tool/source citations.
  - Implement guardrail layer in `src/agents/guardrails.py`:
    - Explicitly clarifies that read-only tool allowlisting is the definitive security boundary.
    - Prompt injection detection (advisory input check rejecting hostile instructions).
    - Content isolation directive: retrieved text is strictly reference data to summarize, never instructions to execute.
  - Comprehensive unit and adversarial tests in `tests/test_agent_graph.py` and `tests/test_agent_guardrails.py`.
- **Per-Ticket Context:** `src/agents/tools.py`, `src/agents/rag/retriever.py`, `docs/Security.md`, `docs/Agents.md`.
- **Files Touched:** `src/agents/state.py`, `src/agents/graph.py`, `src/agents/providers.py`, `src/agents/guardrails.py`, `tests/test_agent_graph.py`, `tests/test_agent_guardrails.py`.
- **Estimated Size:** ~500 lines.
- **Depends On:** M7-1, M7-2.
